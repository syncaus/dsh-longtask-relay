# 长任务接力

## 它解决什么

一个长任务跑久了，上下文一定会满。DSH 的自动压缩会把旧历史摘要掉，让会话继续，但摘要是有损的：细节被压平、决策理由被丢掉，越往后越容易在同一个问题上反复。而顶层会话彼此独立，`list_agents` / `send_message` 只覆盖 subagent 树，一个会话看不到另一个会话在做什么，也无法把自己没做完的事交出去。

这个插件用「会话链」补上这段：一个任务对应一条链，链上有多个会话，同一时刻只有一个在推进。上下文逼近上限时，当前会话先收尾（做完当前最小单元、写进度、跑验证），插件再开一个干净的新会话，把「真理源在哪里、做到第几步、下一步做什么」交给它。旧会话退役，不再自动工作。

## 真理源

链的全部长期记忆在工作区里：

```
<workspace>/.relay/<chainId>/
├── features.json   任务清单，JSON
├── PROGRESS.md     Done / In progress / Next / Errors / Notes
├── HANDOFF.md      给下一个会话的短交接（≤ 60 行）
└── relay.json      插件维护的链元数据：会话列表、交接次数、状态
```

`features.json` 的每条记录：

```json
{
  "id": "F001",
  "title": "登录接口返回 401 时前端跳转登录页",
  "priority": 1,
  "passes": false,
  "evidence": null,
  "verify": "pnpm test auth/redirect.spec.ts",
  "notes": ""
}
```

会话只能改 `passes`、`evidence`、`notes`；不能新增、删除或重命名条目——否则「完成」的定义会被会话自己改写。这条约束由 `relay_checkpoint` 强制执行，`relay_finish` 在还有未通过条目时直接拒绝。

## 一次交接发生什么

1. 会话空闲且上下文比例越过 `handoffRatio`（或压缩次数达到 `handoffAfterCompactions`）。
2. 插件注入一条收尾指令：做完当前功能、重写 `PROGRESS.md`、跑一次验证、重写 `HANDOFF.md`，不要开始新功能。
3. 收尾轮结束、会话再次空闲（或模型调用 `relay_checkpoint(ready=true)`）。
4. 插件创建新会话：同一工作目录、同一 preset，命名成「任务 · 接力 N」，加入同一工作区。
5. 投递交接说明：目标、链 id、交接序号、真理源绝对路径、当前进度、下一件事、热身步骤（读三份文件、跑验证）、以及「一次只做一个功能」的规则。
6. 旧会话收到退役说明，其 goal 被暂停，不再参与判定。

交接说明只给路径和短摘要，不复制对话内容——让新会话从文件重建，而不是继承旧噪音。

## 什么时候会触发

| 条件 | 动作 |
|---|---|
| 上下文比例 ≥ `wrapupRatio`（默认 0.55） | 只在压缩过之后才用来触发收尾 |
| 上下文比例 ≥ `handoffRatio`（默认 0.70） | 进入收尾 |
| 成功压缩 ≥ `handoffAfterCompactions` 且比例 ≥ `compactedRatioFloor` | 进入收尾（压缩过说明吃紧过） |
| 成功压缩 ≥ `hardCompactions`（默认 2） | 不等边界，直接交接 |
| 收尾后空闲超过 `wrapupTimeoutMinutes` | 强制交接 |
| 模型调用 `relay_checkpoint(ready=true)` | 立即允许交接 |

判定只在会话**完全空闲**（没有排队的下一步输入）时进行，所以不会打断正在输入的人类。每次判定之间有 `cooldownMs` 冷却。

## 与自动压缩的关系

`compaction-basic` 默认在窗口的 80% 处压缩。压缩之后压力会掉到很低，本插件看起来就「不该触发」了。所以阈值必须低于压缩线：默认 0.70。如果你把压缩阈值调到 0.9，可以把 `handoffRatio` 调到 0.78，给收尾轮留出余量。

## 面板

侧栏的「长任务接力」列出这个 Host 已知的每条链：状态、功能进度、当前会话、交接次数。展开一条链可以看到每个会话的角色、是否在线、上下文占用、压缩次数，以及完整的功能清单和当前的交接说明。按钮可以暂停/恢复自动交接，或立即交接一次。

面板数据每 5 秒从 Host 重新读取；会话的压缩次数来自一个每会话的投影，所以即使会话没被打开也能看到。

## 限制

- 链结构由插件记录，DSH 本身不维护顶层会话之间的关系。
- 新会话要重新付一遍 system prompt 和工具 schema 的成本。
- 未加载的会话没有实时上下文数字。
- 插件重启后按工作区目录重新发现链；不在任何已知工作区里的链不会出现在面板里，直到打开其会话。
- 一个 Host 进程内不同步到其他进程。
- 委派的 subagent 不能操作链。
